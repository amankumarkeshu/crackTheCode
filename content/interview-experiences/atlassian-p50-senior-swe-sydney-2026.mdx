# Atlassian P50 Senior Software Engineer - Engineering with Heart

## Background

Atlassian stood out to me for their focus on team collaboration tools and strong engineering culture. After 5 years building developer tools, I was excited to contribute to products used by millions of teams worldwide. This breakdown covers my successful P50 (Senior SWE) interview experience in Sydney, including their unique values-driven process.

## Atlassian's Interview Philosophy

Atlassian evaluates candidates through their **TEAM values**:
- **T**eam: Collaboration and helping others succeed
- **E**xcellence: High standards and continuous improvement  
- **A**ccountability: Owning outcomes and learning from mistakes
- **M**utual respect: Inclusive and respectful interactions

**Key Insight**: Unlike other tech companies, Atlassian deeply integrates values assessment throughout the technical process, not just in behavioral rounds.

### Coding Problem 1 (20 minutes)
**Question**: Implement a rate limiter using token bucket algorithm

**My Solution**:
```python
class TokenBucket:
    def __init__(self, capacity, refill_rate):
        self.capacity = capacity
        self.tokens = capacity
        self.refill_rate = refill_rate
        self.last_refill = time.time()
    
    def consume(self, tokens=1):
        self._refill()
        if self.tokens >= tokens:
            self.tokens -= tokens
            return True
        return False
    
    def _refill(self):
        now = time.time()
        tokens_to_add = (now - self.last_refill) * self.refill_rate
        self.tokens = min(self.capacity, self.tokens + tokens_to_add)
        self.last_refill = now
```

### Coding Problem 2 (20 minutes)
**Question**: Design a simple task scheduler that executes tasks at specified intervals

**My Approach**: Used priority queue (heapq) with task objects containing execution time and callback functions.

**Atlassian Focus**: They emphasized code readability, error handling, and how I'd test the solution - very practical engineering mindset.

## Virtual Onsite Loop (4 Rounds)

### Round 3: Coding & Data Structures (60 minutes)

**Problem**: Implement a distributed cache with LRU eviction

**Requirements**:
- Thread-safe operations
- O(1) get and put operations
- Configurable capacity
- Statistics tracking (hit rate, miss rate)

**My Implementation**:
- Used HashMap + Doubly Linked List for O(1) operations
- ReentrantReadWriteLock for thread safety
- AtomicLong for statistics tracking
- Comprehensive error handling and edge cases

**Atlassian Evaluation Criteria**:
- Code quality and readability
- Thread safety considerations
- Performance optimization
- Testing strategy
- Production-ready error handling

**Key Differentiator**: They asked me to walk through how I'd code review this solution - testing collaborative mindset.

### Round 4: Code Design & Craft (60 minutes)

This was Atlassian's most unique round - focused on real-world coding rather than algorithmic problems.

**Challenge**: Build a webhook delivery system for Jira/Confluence

**Requirements**:
- Reliable delivery with retries
- Rate limiting per subscriber
- Failure handling and dead letter queue
- Monitoring and observability
- Scalable architecture

**My Design Process**:

1. **API Design** (15 min)
   - RESTful endpoints for webhook registration
   - Event payload structure
   - Authentication mechanisms

2. **System Architecture** (20 min)
   - Event queue (Apache Kafka/RabbitMQ)
   - Worker services for delivery
   - Database for subscriber management
   - Monitoring dashboard

3. **Implementation Details** (25 min)
   - Exponential backoff retry logic
   - Circuit breaker for failing endpoints
   - Batch processing for efficiency
   - Security considerations (HMAC signatures)

**Atlassian Focus**: Heavy emphasis on how this would integrate with existing Atlassian products and real operational concerns.

### Round 5: System Design (60 minutes)

**Problem**: Design a notification system for Atlassian products (Jira, Confluence, Trello)

**Scale Requirements**:
- 100K+ organizations 
- 10M+ users globally
- Multiple notification channels (email, Slack, mobile)
- Real-time delivery for urgent notifications

**My Approach**:

1. **Requirements Gathering** (10 min)
   - Functional: Multi-channel delivery, user preferences, notification types
   - Non-functional: Low latency, high availability, scalability

2. **High-Level Architecture** (20 min)
   - Event-driven architecture with pub/sub
   - Notification service with pluggable channels
   - User preference service
   - Analytics and monitoring

3. **Deep Dives** (30 min)
   - **Message Queue Design**: Kafka partitioning strategy
   - **Channel Abstraction**: Unified interface for email/Slack/push
   - **User Preferences**: Real-time updates and caching
   - **Delivery Guarantees**: At-least-once with deduplication

**Atlassian-Specific Considerations**:
- Integration with existing product APIs
- Compliance requirements (GDPR, data residency)
- Multi-tenant architecture
- Customer-specific notification rules

### Round 6: Values Interview (60 minutes)

Pure behavioral round assessing alignment with Atlassian's TEAM values:

#### Team (Collaboration)
**Question**: "Tell me about a time you helped a struggling team member"

**My Example**: Mentored a junior developer through a complex feature implementation, pair programming sessions led to successful delivery and their promotion.

#### Excellence (High Standards)
**Question**: "Describe a situation where you pushed back on lowering quality standards"

**My Example**: Insisted on proper testing for a rushed feature, prevented production bugs that could have cost $100K+ in SLA penalties.

#### Accountability (Ownership)
**Question**: "Tell me about a mistake you made and how you handled it"

**My Example**: Deployed a configuration change that caused API latency spike, immediately rolled back, conducted post-mortem, implemented monitoring to prevent recurrence.

#### Mutual Respect (Inclusivity)
**Question**: "How do you ensure all team members feel heard in technical discussions?"

**My Example**: Structured team meetings to give everyone speaking time, created async RFC process for introverted team members to contribute.

**Key Success Factor**: Atlassian wants specific examples showing genuine care for team dynamics and inclusive collaboration.
