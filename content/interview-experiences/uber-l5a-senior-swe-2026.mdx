# Uber L5A Senior Software Engineer - Production Engineering at Scale

## Background

After 6 years building backend systems and seeing Uber's impact on transportation and logistics, I decided to pursue their L5A (Senior Software Engineer) role. Uber's interview process is known for being particularly rigorous, focusing heavily on production-ready code and real-world system design challenges. This breakdown covers my successful journey through their 5-round marathon.

## Uber's Interview Philosophy

Uber evaluates candidates through their core engineering principles:
- **Production-First Mindset**: Code that actually works in real systems
- **Scale Awareness**: Building for millions of users and thousands of cities
- **Marketplace Dynamics**: Understanding two-sided platforms (riders & drivers)
- **Operational Excellence**: Systems that don't break at 2 AM

**Key Insight**: Uber cares more about engineers who can ship reliable systems than those who solve abstract algorithmic puzzles perfectly.

- **Application**: October 2025 (employee referral)

## Round 2: Coding BPS - Elimination Round (1 hour)

**BPS = "Basic Problem Solving"** - but don't let the name fool you. This is a make-or-break round.

### Problem: Rate Limiting for Uber's API Gateway

Design and implement a distributed rate limiter that:
- Handles 100K+ requests per second
- Supports multiple rate limiting strategies (per-user, per-IP, per-API)
- Provides real-time monitoring and alerting
- Gracefully degrades under high load

**My Solution Approach**:

```python
import time
import threading
from collections import defaultdict
from enum import Enum

class RateLimitStrategy(Enum):
    FIXED_WINDOW = "fixed_window"
    SLIDING_WINDOW = "sliding_window"
    TOKEN_BUCKET = "token_bucket"

class DistributedRateLimiter:
    def __init__(self, redis_client, strategy=RateLimitStrategy.TOKEN_BUCKET):
        self.redis = redis_client
        self.strategy = strategy
        self.local_cache = defaultdict(dict)
        self.cache_ttl = 60  # seconds
    
    def is_allowed(self, key: str, limit: int, window_seconds: int) -> bool:
        """
        Check if request is allowed under rate limit
        Returns: (allowed: bool, retry_after_seconds: int)
        """
        try:
            if self.strategy == RateLimitStrategy.TOKEN_BUCKET:
                return self._token_bucket_check(key, limit, window_seconds)
            elif self.strategy == RateLimitStrategy.SLIDING_WINDOW:
                return self._sliding_window_check(key, limit, window_seconds)
            else:
                return self._fixed_window_check(key, limit, window_seconds)
        except Exception as e:
            # Fail open - allow requests if rate limiter is down
            self._log_error(f"Rate limiter error: {e}")
            return True
    
    def _token_bucket_check(self, key: str, limit: int, refill_period: int) -> bool:
        now = time.time()
        bucket_key = f"rate_limit:token_bucket:{key}"
        
        # Lua script for atomic operations in Redis
        lua_script = """
        local bucket_key = KEYS[1]
        local limit = tonumber(ARGV[1])
        local refill_rate = tonumber(ARGV[2])
        local now = tonumber(ARGV[3])
        
        local bucket = redis.call('HMGET', bucket_key, 'tokens', 'last_refill')
        local tokens = tonumber(bucket[1]) or limit
        local last_refill = tonumber(bucket[2]) or now
        
        -- Calculate tokens to add
        local elapsed = now - last_refill
        local tokens_to_add = elapsed * refill_rate
        tokens = math.min(limit, tokens + tokens_to_add)
        
        if tokens >= 1 then
            tokens = tokens - 1
            redis.call('HMSET', bucket_key, 'tokens', tokens, 'last_refill', now)
            redis.call('EXPIRE', bucket_key, 3600)
            return 1
        else
            redis.call('HMSET', bucket_key, 'tokens', tokens, 'last_refill', now)
            redis.call('EXPIRE', bucket_key, 3600)
            return 0
        end
        """
        
        refill_rate = limit / refill_period
        result = self.redis.eval(lua_script, 1, bucket_key, limit, refill_rate, now)
        return bool(result)
```

## Virtual Onsite Loop (4 Rounds)

### Round 3: Algorithms and Data Structures (1 hour)

**Structure**: 3 problems of increasing difficulty, 15-20 minutes each

#### Problem 1: Dynamic Programming - Optimal Driver Routing
**Question**: Given a driver's location and multiple ride requests, find the optimal sequence to maximize earnings while minimizing total distance.

**My Approach**:
- Modeled as traveling salesman variant with profit optimization
- Used dynamic programming with bitmask for visited rides
- Time complexity: O(n² × 2ⁿ) - acceptable for n ≤ 15 rides

#### Problem 2: Graph Algorithms - Surge Pricing Zones
**Question**: Design an algorithm to identify optimal surge pricing zones based on supply/demand imbalance.

**My Solution**:
- Represented city as weighted graph with demand/supply ratios
- Used modified connected components algorithm
- Applied k-means clustering for zone optimization

#### Problem 3: System Design Logic - ETA Calculation
**Question**: Design the core algorithm for calculating accurate ETAs considering real-time traffic.

**My Approach**:

Build a service that matches riders with nearby drivers, considering:

```python
from typing import List, Dict, Optional
from dataclasses import dataclass
from enum import Enum
import asyncio
import logging

@dataclass
class Location:
    latitude: float
    longitude: float
    timestamp: int
    
    def distance_to(self, other: 'Location') -> float:
        """Calculate haversine distance in meters"""
        # Implementation with proper earth radius calculations
        pass

@dataclass
class RideRequest:
    request_id: str
    rider_id: str
    pickup_location: Location
    destination: Location
    vehicle_type: VehicleType
    max_wait_time: int  # seconds
    created_at: int

class MatchingService:
    def __init__(self, 
                 driver_service: DriverService,
                 pricing_service: PricingService,
                 eta_service: ETAService,
                 fraud_service: FraudService):
        self.driver_service = driver_service
        self.pricing_service = pricing_service
        self.eta_service = eta_service
        self.fraud_service = fraud_service
        self.logger = logging.getLogger(__name__)
    
    async def find_match(self, ride_request: RideRequest) -> Optional[MatchResult]:
        """
        Find optimal driver match for ride request
        Returns None if no suitable match found
        """
        try:
            # Fraud check first
            if not await self.fraud_service.validate_request(ride_request):
                self.logger.warning(f"Fraud detected for request {ride_request.request_id}")
                return None
            
            # Get available drivers in radius
            nearby_drivers = await self.driver_service.find_nearby_drivers(
                location=ride_request.pickup_location,
                radius_km=5.0,
                vehicle_type=ride_request.vehicle_type
            )
            
            if not nearby_drivers:
                return None
            
            # Calculate match scores for each driver
            match_candidates = []
            for driver in nearby_drivers:
                match_score = await self._calculate_match_score(
                    ride_request, driver
                )
                if match_score > 0.6:  # Configurable threshold
                    match_candidates.append((driver, match_score))
            
            # Sort by match score and select best
            match_candidates.sort(key=lambda x: x[1], reverse=True)
            
            if match_candidates:
                best_driver, score = match_candidates[0]
                return await self._create_match_result(ride_request, best_driver)
            
            return None
            
        except Exception as e:
            self.logger.error(f"Matching error for {ride_request.request_id}: {e}")
            # Return None for graceful degradation
            return None
    
    async def _calculate_match_score(self, 
                                   request: RideRequest, 
                                   driver: Driver) -> float:
        """Calculate match score based on multiple factors"""
        
        # Distance score (closer is better)
        distance = request.pickup_location.distance_to(driver.location)
        distance_score = max(0, 1.0 - (distance / 2000))  # 2km max
        
        # ETA score
        eta = await self.eta_service.calculate_eta(
            driver.location, request.pickup_location
        )
        eta_score = max(0, 1.0 - (eta / request.max_wait_time))
        
        # Driver rating score
        rating_score = driver.rating / 5.0
        
        # Driver utilization (prefer active drivers)
        utilization_score = min(1.0, driver.trips_today / 20.0)
        
        # Weighted combination
        total_score = (
            distance_score * 0.4 +
            eta_score * 0.3 +
            rating_score * 0.2 +
            utilization_score * 0.1
        )
        
        return total_score
    
    async def _create_match_result(self, 
                                 request: RideRequest, 
                                 driver: Driver) -> MatchResult:
        """Create final match result with pricing"""
        
        eta = await self.eta_service.calculate_eta(
            driver.location, request.pickup_location
        )
        
        base_price = await self.pricing_service.calculate_price(
            pickup=request.pickup_location,
            destination=request.destination,
            vehicle_type=request.vehicle_type
        )
        
        surge_multiplier = await self.pricing_service.get_surge_multiplier(
            location=request.pickup_location,
            time=request.created_at
        )
        
        final_price = base_price * surge_multiplier
        
        return MatchResult(
            request_id=request.request_id,
            driver_id=driver.driver_id,
            eta_seconds=eta,
            estimated_price=final_price,
            surge_multiplier=surge_multiplier
        )
```

### Round 5: System Design - Marketplace Architecture (1 hour)

**Problem**: Design Uber's core trip lifecycle system

**Requirements**:
- Handle 15M trips per day globally
- Real-time location tracking for 5M active vehicles
- Sub-second matching for ride requests
- 99.99% availability during peak hours
- Support for multiple vehicle types and service tiers

**My Architectural Approach**:

#### High-Level Architecture
1. **API Gateway**: Rate limiting, authentication, request routing
2. **Matching Service**: Real-time driver-rider pairing
3. **Location Service**: Vehicle tracking and geospatial queries
4. **Trip Service**: Lifecycle management (request → completion)
5. **Pricing Service**: Dynamic pricing and surge calculation
6. **Payment Service**: Transaction processing and billing
7. **Notification Service**: Real-time updates to apps

#### Deep Dive: Real-Time Location Service

**Challenge**: Track 5M vehicles with 30-second update frequency

**My Solution**:
- **Ingestion**: Apache Kafka for location stream processing
- **Storage**: Redis Cluster for hot data + Cassandra for historical
- **Geospatial Queries**: Redis with GEORADIUS for nearby driver searches
- **Partitioning**: Shard by geographic regions (city-level)

**Data Model**:
```sql
-- Hot location data (Redis)

  status: "available"

-- Historical tracking (Cassandra)
CREATE TABLE driver_locations (

  PRIMARY KEY ((driver_id, date), timestamp)
) WITH CLUSTERING ORDER BY (timestamp DESC);
```

#### Deep Dive: Matching Service Scalability

**Challenge**: Match 1000+ ride requests per second

**My Approach**:
1. **Regional Sharding**: Separate matching clusters per city/region
2. **Load Balancing**: Consistent hashing based on pickup location
3. **Caching**: Pre-computed driver pools per geographic grid
4. **Async Processing**: Event-driven architecture with message queues

**Matching Algorithm**:
- **Spatial Indexing**: Geohash-based driver clustering
- **Score Calculation**: Multi-factor optimization (distance, ETA, rating)
- **Conflict Resolution**: Distributed locks to prevent double-matching

#### Bottlenecks and Solutions

**Location Update Bottleneck**:
- Problem: 5M drivers × 30sec updates = 167K writes/sec
- Solution: Batch updates, write-behind caching, geographic partitioning

**Matching Latency**:
- Problem: Sub-second matching requirements
- Solution: Pre-computed driver pools, in-memory indexes, regional deployment

**Database Scaling**:
- Problem: High read/write load on trip data
- Solution: Read replicas, CQRS pattern, event sourcing

**Uber-Specific Considerations**:
- **Surge Pricing Integration**: Real-time demand monitoring
- **Driver Incentives**: Batch job for earnings calculations  
- **Regulatory Compliance**: Data residency and driver background checks
- **Fraud Prevention**: Real-time anomaly detection
